## 0. 目标与原则

1. **可用**：用一份真实简历 + 真实校招 JD，完整跑通「上传 → 诊断 → 优化 → 选岗位 → JD 解析 → 匹配 → 定向优化 → 存版本 → 记录投递」闭环。
2. **可信**：匹配度从“AI 随口打分”升级为“可解释的规则 + 向量/AI 混合评分”，每一项分都有依据。
3. **可展示**：最终形态本身是作品（网关 + 微服务 + Redis 缓存 + AI 抽象 + 数据隔离 + React 前端），适合秋招项目介绍。
4. **需求文档为准**，但按价值排优先级；差距项在文档中标记状态，不闷头做全部 V2.0 功能。

### 4.1 修正

- `POST /api/v1/match/body`：当前用 `@RequestParam` 收 JSON Body，收不到；改为 DTO `{resumeId, jobId}`。


## 5. 后端实施指引

### 5.1 P0 顺手修的已知问题

1. `server-app` 聚合 jar 是薄 jar，不能 `java -jar` 独立跑；标注废弃或从 `<modules>` 摘除。
2. `start-dev.ps1` 过时；README/注释不再提单体 8088。
3. 每个服务 schema.sql 全量建 7 张表没问题（共享库），但注释写清“共享库过渡期”。
4. `/internal/**` 目前裸放行：加 `X-Internal-Token` 请求头校验（各服务配置同一环境变量），或在网关层拦掉外部访问。
5. `OptimizeController`/`ResumeVersionController` 补导出路由，调现有 `exportVersion()`。
6. 匹配 JSON 解析失败时给出友好错误，不把 AI 原文抛给前端。

### 5.2 服务健康与日志

- 每个服务保留 `/actuator/health`；网关把 `/actuator/health` 转发 auth-service。
- 启动脚本轮询 5 个端口 + Nacos 控制台确认注册成功后再结束。

### 5.3 安全与数据隔离

- 所有业务接口统一 `AuthContext.getUserId()`；删除“用 selectById 但不校验 user_id”的写法。
- 简历/版本/诊断/匹配/投递全部按 user_id 查询。
- JWT secret 与 AI key 只走 `.env`；仓库内已有真实 key 的 `.env` 确保进 `.gitignore`（检查后补）。

### 5.4 匹配引擎（需求 3.4.4 的真实实现）

建议接口返回扩展后的 MatchResult：

```json
{
  "overallScore": 72,
  "keywordCoverage": 65,
  "semanticSimilarity": 78,
  "hardRequirementScore": 60,
  "hardRequirementPassed": false,
  "keywordHits": [{"keyword":"Java","hit":true}, ...],
  "missingKeywords": ["Kafka", "分布式事务"],
  "matchExplanation": "……",
  "dimensionDetails": {}
}
```

评分流程（可先在 job-match 服务实现，AI 只做“关键词抽取/同义词归一/解释生成”）：

1. **关键词覆盖度（40%）**
   - 用 AI（或规则+同义词表）把 JD 拆成核心关键词集，去掉停用词。
   - 简历文本与关键词做归一化匹配（包含大小写/中英文/同义词表），算 `命中数/核心词数*100`。
   - 输出 keywordHits 明细，供前端渲染“命中/缺失标签”。
2. **语义相似度（40%）**
   - 有 embedding Key：简历/JD 各自 embedding，余弦相似度映射到 0~100。
   - 无 Key：降级为 AI 对“语义贴合度”打分（前端标注“近似值”），后续有 Key 自动切换。
3. **硬性条件（20%）**
   - 规则解析 JD 的学历/年限要求；简历用“已解析字段 + AI 识别教育/经历”对照。
   - 给出 hardRequirementScore 与 passed 布尔。
4. **综合与封顶**
   - `overall = keyword*0.4 + semantic*0.4 + hard*0.2`。
   - 学历/年限不满足时 overall 封顶 40，并在 explanation 点名。
5. 结果缓存 Redis（1h + 随机偏移），命中直接返回。

同一简历同一岗位优化后再次匹配，即可得到“47 → 84”的对比，前端展示变化原因（diff 改动项即原因）。
